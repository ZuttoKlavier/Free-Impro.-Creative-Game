# iOS 现场验收与节奏交付故障

记录截至 2026-10-21，北京时间。以下严格区分本机备份检查、用户现场反馈、隔离接口复现及尚未完成的云端修复验收。

## 已有证据

2026-10-20 晚，连接到 Mac 的 iPhone 上可以打开学生 App。一次设备元数据读取显示 `0.3.0 (2026102002)`，为开发签名安装；镜像显示声音库徽标为 5。更新前已将该 App 容器只读复制到本机受限目录，不上传作品、照片、Cookie 或凭据。

备份中有 5 条声音记录、0 项待发队列，5 个关联 PCM WAV 文件均存在且可读，没有缺失的外部文件引用。核验前后源备份文件哈希一致。逐记录 key/value 与音频哈希、一致性快照保存在 `data/ios-release-acceptance-2026-10-20/before/`，不提交或公开备份内容。WebKit 的私有 `IDBKEY` 排序规则不能由普通 SQLite 完整验证；已明确区分规范化审计快照的完整性检查与原 WebKit 库的完整性检查。

| 操作 | 用户现场结果 | 证据边界 |
| --- | --- | --- |
| 试听旧作品 | 正常听到 | 未由工具采集实际扬声器输出 |
| TestFlight 覆盖更新 | 用户报告更新到 `2026102003`，5 份旧作品仍在且能试听 | 后续设备读取仍曾显示 `2002`；2026-10-21 用户表示测试连接已删除、无法查看。构建号与设备对应关系仍待复核，不能记成独立验证的 `2003` 升级通过 |
| 新录约 3 秒、保存并回听 | 用户报告保存成功、声音清楚 | 尚未取得更新后逐记录对比或新音频哈希 |
| 提交作品到测试课堂 | 用户报告手机显示已接收或已启用 | 不等于教师已收到完整节奏或已完成合奏回听 |
| 节奏编创交付 | 用户报告教师端只收到单音，无法收到编创内容 | **故障未通过；停止将该链路计为验收成功** |

TestFlight 外部组中 `2026102003` 的“正在测试”和安装记录另见 [TestFlight 发布记录](testflight-2026-10-19.md)。其他测试员的安装记录不能证明本次连接到 Mac 的手机已经更新。

## 独立复现

2026-10-21，对记录中的旧云业务源码和冻结候选分别启动仅监听本机的内存课堂服务，发送相同的合成 WAV 和包含长音的节奏。没有访问生产数据库或创建公网业务对象。

- 旧版本 `server/app.js`（SHA256 `63ba77a5d9d3dc27d40828c6225381efe50043fa86b409f24c0454f19e295900`）返回 201，保存了音频，但未保存随作品提交的 `rhythm`，教师轨道也不匹配。
- 冻结候选（SHA256 `5aea852ae6af77fe01d8a16a23490eafc59431265193f0227d27165bf4c63751`）同样返回 201，并完整保留 `rhythm`、将对应长音节奏应用到教师轨道。

复现脚本和限定结果为 `output/release-followup-2026-10-20/compare-rhythm-delivery.mjs`、`rhythm-delivery-comparison.json`。这证明旧版本存在相符缺陷；实时云端运行文件仍应由统一发布流程核实，不能仅凭该复现认定云端已经更新。

## 发布后继续验收

云端更新由“修复课堂同步与节奏编创”聊天统一执行。本聊天已获用户授权协调，修复白名单、哈希、移动端状态与证据边界保存在 `output/classroom-release-coordination-2026-10-21/mobile.json`；本聊天不并行 Apply 或覆盖其他发布目录。

更新及正常可信 HTTPS 复验完成后，须确认实际安装构建、教师网页与服务版本，再用原测试课堂验证：

1. 保留现有作品，选择一份已保存的节奏提交；教师确认轨道中的触发位置和长音与原稿一致。课堂循环长度对节奏的重复或裁切规则单独核对。
2. 教师开始合奏，实际听到节奏；作品等待区的原始采样试听与合奏播放分开判断。
3. 更换声音或节奏时，核对待接受状态、教师审批，以及播放中的下一遍循环切换；不能提前替换旧声音。
4. 刷新和短暂断网恢复后保持同一有效身份，不重复占位、不重复提交；明确退出仍撤销会话。

目前尚未完成教师完整节奏回听、发布后的真机复验、真实移动网络与断网恢复、iPad 或 15/50 台设备规模验收。以上局部反馈不能用于宣布正式发布。
