第二轮的 `manifest.json` 保存受测原生、网页、课堂及服务文件的 SHA-256。修复包构建和 Lint 成功不计作真机通过。构建曾选中另一份已存在的本地测试密钥，该中间包被系统以 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 拒绝；随后使用原有测试密钥重新签名，核对指纹与 v2 签名后覆盖安装成功。中间包保留为 `.blocked`，没有卸载、清数据或创建新签名密钥。

共用前置：

1. 教师与手机在同一非隔离 Wi-Fi，电脑唤醒，允许课堂 HTTPS 入站；手机填写电脑 LAN 地址，手机的 `localhost` 不是电脑。确认双方连接**同一服务、同一数据库、同一课堂**。
2. 保留现有 CA；停止共享同一库的重复服务。LAN IP 变化时重签包含新 IP 的站点证书，保留 CA。更换 CA 要重建客户端；不改 HTTP、不放宽来源或忽略 TLS。
3. 使用正式网页构建，在线等候“已准备离线创作”。Android 页面来自配置的 HTTPS 来源及 Service Worker，不能套用 iOS 随包离线页面、冷开零请求或断网立即退出行为，见 [离线初始化](../src/offline.js)、[课堂传输](../src/classroom-transport.js)。
4. 权限拒绝/恢复可通过系统权限设置操作；不得清除应用数据或卸载来重置权限。安装/迁移/升级前先导出并验证备份；升级失败保留旧包、旧来源和原数据。
5. 公开域名路径须另满足有效公开 HTTPS 与部署开放条件，单独完成闭环；LAN 通过不能外推公网、其他品牌/系统、最低 API 29 或 15/50 人课堂。

## 4. 采集与数据库最小检查点

每个子步骤记录 `run_id、case_id、匿名device_id、时间、操作、class_id、匿名student_id、requestId/submission_id/revision、HTTP状态或错误、预期、实测、证据路径、结论`。未采集填“未采集”，不能填0当作零错误/零延迟。画面不足以证明后台释放时，结合系统指示器/权限状态和生命周期；采集不可用则该项证据不足。

服务日志：macOS 后台通常为 `data/classroom-service.log`，前台使用对应标准输出/错误；手机保留有时间边界的进程/Activity/权限/崩溃日志。现有业务错误日志不是完整访问日志，`/api/health`不检查数据库。WebView调试关闭，不得为通过验收临时放宽来源或开放任意调试入口；请求关联不足时明确列为观测缺口。

| --- | --- | --- |

## 5. no-go 与回滚共用规则

1. 任一TLS绕过、错人错课/越权、本地库丢失或数据库损坏：立即停本轮；停止新连接、上传、审批，必要时停止教师输出，保留故障前后日志、UI、未确认队列、本地库及一致性快照。其他未测项目不能补填通过。
2. 单项功能失败可记录后停止依赖该项的流程；不以浏览器/模拟器成功补上，不把重试成功抹去首次失败。修复或更换候选后新建轮次，复验受影响项目。
3. 恢复网络和原课堂目标；同一来源下优先导出本地库。回退兼容旧包/服务前确认签名和数据兼容性，先备份再覆盖；不卸载、不清应用/站点数据、不任意改IP/端口。换来源必须执行导出→切换→导入。
4. 服务重启或教师长断连后，不承诺时间轴无缝恢复；先停旧输出、关闭其他演奏窗口，读取最新快照并核对accepted与唯一控制权，再人工加载/开播。
5. 数据库回滚独立决策：优先旧程序继续使用当前兼容库；如需恢复旧库，停服并保存故障后快照、列清新增写入，再采用已验证恢复流程。不能直接覆盖当前库、漏掉WAL或将旧current改状态当作恢复媒体。
6. 本轮最多得出“指定小米系统/WebView、指定APK/网页/服务、指定LAN、指定教师设备的限定配置通过”。不能据此标记安卓端可发布、公开HTTPS已上线、所有品牌已测或15/50人课堂通过。

## 7. 2026-10-20 会话连续性隔离复核

本次只使用临时内存数据库、本机随机端口与独立测试浏览器，没有读取或修改原现场数据库，也没有操作手机。以下是新的代码与测试环境证据，不回填为 10 月 16～17 日真机通过结果，不改变原始失败记录。

1. **同一有效会话重复入课的代码 race 已复现并修复。** 原 `/api/student/enter-classroom` 即使保留同一学生 UUID，也会删除旧会话并下发新 Cookie。多个预先携带同一有效 Cookie 的并发或重试请求中，首个请求会使后续请求的会话失效；后续请求可能因此新建游客 UUID，重复占据课堂名额。工作区 `server/app.js` 现只在身份发生变化或没有有效身份时签发新会话；同一有效身份重入保留原会话。新增 `tests/student-session-continuity.test.js` 的 3 项回归在修复前为 1 失败、2 通过，修复后全部通过；连同课堂、账号、角色隔离、原生登录及身份恢复相关测试共 46 项通过。不同设备的同名游客仍保持独立；过期会话不能认领原身份；明确切换身份与退出仍撤销旧会话。该修复没有合并或删除旧现场的任何身份、作品或名额。
2. **跨端口测试环境的 Cookie 冲突也已独立复现。** 在同一桌面 Chrome 的独立测试 Cookie 容器中，两个 `127.0.0.1` HTTP 随机端口各连一个独立内存课堂库：A 入课成功 → B 入课成功 → 回到 A 的 `/me` 返回 401 → A 重新入课生成不同 UUID，A 成员数增至 2。浏览器只保留一个同名 `fi_session_student` Cookie；独立端口和独立数据库不构成 Cookie 隔离。此环境问题未通过重命名全栈 Cookie 处理；并行隔离验收须使用不同主机名或独立 Cookie 容器，不能仅换端口。固定公网单一来源不等于这个双服务测试场景，也不能从此复现推断其已发生同样冲突。
3. **旧现场根因仍未证，新真机复验仍待。** 原现场缺少导致会话轮换的完整请求、响应和设备操作链，不能认定是以上任一原因。须以包含本次服务修复的冻结候选，在同一明确课堂来源、隔离 Cookie 环境中重新验证 A07 同 UUID 重复连接、A09 离线恢复后的身份与待发队列、A08 明确退出撤销，并记录 UUID、成员/slot、请求时间及服务版本。完成前保留该真机会话项 no-go；自动化修复通过不能替代设备验收。
