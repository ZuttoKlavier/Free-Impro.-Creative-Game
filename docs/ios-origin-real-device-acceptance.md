**现场顺序与回滚底线**

当前固定公网包建议按 P0/PD → PC 当轮可用性 → M6 首装或升级冷开 → M4 离线素材 → M2/M5 → M1/M3 移动网络闭环 → M7 执行。历史 LAN 包仅在确需兼容验收时单列 PL，不修改当前包的固定目标。同一设备、同一包已有可追溯的局部真机结果可复用；更换相关客户端、证书、来源或服务器后只重验受影响项，不重跑与版本无关的全部业务测试。没有现场证据的格子填“待执行”或“前置阻塞”，不能填通过。

公开启用失败的部署回滚由管理员先核对服务路径和归属，再停止本次 HTTPS 服务、处理其专用规则，必要时按同目录 WinSW wrapper 卸载对应服务；私有课堂后台保留或恢复。程序更新回退先停 HTTPS、再停课堂，恢复旧程序/网页及兼容依赖，先验证本机课堂与正确 Host，再仅在公开阶段原本已获准时恢复 HTTPS。保留 `data`、`backups`、`caddy-data` 与当前数据库；若版本涉及不兼容数据变化，停止回退并核对迁移方案，不能直接覆盖旧数据库而抹掉新提交。不要盲目重跑首次安装脚本。

本矩阵通过只支持所记录设备、版本和网络上的最小课堂闭环。15/50 台设备负载、长时间稳定性、蓝牙、真实生图、正式 App Store 发布、大备份与卸载/跨设备恢复仍需单独验收。TestFlight `2003` 的分组和安装已有独立记录，现场仍须核对本次实际安装构建，不能由安装事实或旧构建批准自动推定功能通过。若没有当轮安卓真机结果，结论只能覆盖 iOS，不能写“安卓/iOS 均通过”。
