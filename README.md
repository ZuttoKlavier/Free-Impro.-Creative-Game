# Free Impro · 学生端基础版

当前实现声音采集、本地声音库、账号登录及课堂提交，面向安卓平板浏览器；配有教师课堂接收与更换审批页。声音仅在明确提交后传到本地课堂服务。尚未接入蓝牙、角色生成和教师节奏播放。完整需求见 [designdocument.md](designdocument.md)。

## 本地启动

需要 Node.js 24.15+（使用内置 SQLite）。

```sh
npm install
npm start
```

一次启动前端（5173）和课堂 API（3001）。也可以分别运行 `npm run dev` 和 `npm run server`。电脑打开 http://localhost:5173。点击“试试示例声音”可以体验三个合成敲击的自动切分；示例不会自动保存。

录音使用浏览器 MediaRecorder，必须在 HTTPS 或本机 localhost 下运行并授权麦克风。安卓通过普通局域网 HTTP 地址打开时通常无法录音，需要配置受设备信任的 HTTPS；未将开发服务器部署到公网。HTTPS 部署方案和安卓真机验证需后续完成。

## 已实现

- 最长 15 秒录音，自动停止并释放麦克风；切换到后台也结束录音。
- 自动识别多个声音起点，逐片试听；灵敏度重切分和手动选片。
- 波形支持鼠标和触摸拖动框选、拖动选区整体移动、拖动两端裁切，与下方精调滑块同步；保存采样最长 1 秒。切点应用 3 ms 淡入淡出减少爆音。
- 音频导入（浏览器支持的格式，最大 25 MB）；超过 15 秒只处理前 15 秒并提示。
- 基于 IndexedDB 的本地声音库，最多 200 份；命名、试听、重命名、删除、导出 WAV。
- JSON 整库本地备份与合并导入；相同 ID 跳过，新增作品超额或备份无效时不部分写入。
- 学生／教师账号注册、登录、退出；服务端密码使用随机盐 scrypt，登录会话放在 HttpOnly Cookie 中。
- 教师创建课堂（1–50 人）、课堂码与二维码、满员等待和人数扩容。
- 学生选择本地声音提交；首次提交直接接收，更换需教师接受，未接受时原作品保留；重复请求不会重复写入。
- 教师查看本课堂成员及音频，试听、接受或拒绝最新更换；学生只能查看自己的提交。
- 待发送队列保存在 IndexedDB，按用户和课堂隔离。断线后可手动重试，连接恢复时自动发送。
- 平板和窄屏布局；麦克风拒绝、存储失败、无明显声音、无效备份均有提示。

自动切分使用短时能量和能量突增检测；环境噪声、连贯人声可能需要手动裁切。原始录音仅保留在当前页面内存，保存的采样进入本地库。当前阶段每份作品是声音素材，后续加入形象绑定。

## 数据和离线边界

作品保存在当前浏览器、当前网站来源下。清除网站数据、使用另一浏览器或更换端口不会自动共享作品，请使用备份导出与导入。达到 200 份时不自动删除旧声音。

页面已经加载后，声音采集、处理和保存不需要互联网。账号和课堂存储在运行服务的电脑 `data/classroom.sqlite` 中；数据库（含音频和账号）已加入 gitignore，不提交到 GitHub。服务重启保留记录。

同一 Wi-Fi 内，所有设备必须访问同一台电脑的前端地址，账号、课堂和音频由这台电脑的本地 API 统一处理；API 仅监听本机，由前端代理提供访问。没有互联网但本地服务可达时可正常使用课堂功能；本实现没有云端账号服务。

服务不可达时，只显示上次缓存的身份与课堂记录，新的课堂码不能离线验证；可以准备待发送作品。恢复连接后重新验证真实登录会话，过期需要重新登录。缓存身份不能绕过服务端鉴权。首次注册或登录要求账号服务可达；尚未区分互联网账号和局域网身份服务。退出必须成功撤销服务端会话，断网时提示恢复连接再退出。

本阶段尚未加入应用安装和离线页面缓存，不承诺关闭页面后无服务器也能重新打开。图像、蓝牙和教师节奏播放未实现。教师接受更换只更新课堂接收素材，没有执行 loop 音频切换；下一阶段接入播放引擎时，须按设计文档在下一遍 loop 起点启用。

本地声音库目前按设备浏览器保存，不按登录账号分库；课堂列表、待发送队列和服务端访问权限按账号隔离。

## 验证

```sh
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

也可使用本机已安装的 Chrome：`PLAYWRIGHT_CHANNEL=chrome npm run test:browser`。浏览器测试包含声音流程和两套独立账号的课堂流程；尚未进行安卓真机测试。

单元测试涵盖独立敲击、尾音重叠、静音、裁切限制、WAV 和 200 份原子容量限制。浏览器测试涵盖切分至备份恢复流程、刷新后持久化、15 秒 MediaRecorder 自动停止、权限拒绝和响应式布局。浏览器录音测试使用合成麦克风，不替代安卓真实设备录音测试。

技术参考：[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[MDN MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)。

## 体验账号与课堂

1. 在“我的课堂”注册教师账号，创建课堂，记下 6 位课堂码。
2. 使用另一浏览器或独立浏览器会话注册学生账号，输入课堂码。不同标签页共享账号会话，教师与学生测试请使用独立会话。
3. 学生录制／导入声音并保存，在课堂页面或声音库选择“提交到课堂”。
4. 教师刷新查看和试听；学生再次提交时产生更换申请，教师可接受或保留原声音。
5. 课堂页面可见时约每 8 秒刷新，亦可手动刷新。

二维码中的域名与教师当前访问地址一致。教师若使用 localhost，平板扫码无法指向教师电脑；跨设备请使用可访问的同一局域网地址（录音仍需要 HTTPS）。

`FREE_IMPRO_DB` 可指定课堂数据库文件，`API_PORT` 可修改 API 端口（同时需修改前端代理）。HTTPS 部署时应设置 `COOKIE_SECURE=true`，代理保留原始 Host 和 Origin。本地开发没有邮件验证、密码找回或学校统一身份接入；当前注册允许选择学生或教师角色，每位教师只能管理自己创建的课堂。
